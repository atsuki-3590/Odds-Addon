# 賭式ごとの比較方法・計算方法

ボートレースの 7 賭式について、「同じ的中条件を別の賭式の組み合わせで買う」と
どちらが得かを比べる方法をまとめたものです。

実装済みは **2連複 vs 2連単2点** だけです（`src/calc.js`）。ほかの比較は設計メモです。

---

## 1. 共通の考え方

### 1.1 同じ事象を別の賭式で買う

賭式 T の 1 点（オッズ C）が当たる条件が、別の賭式の n 点（オッズ o₁…oₙ）の
**どれか 1 点だけが必ず当たる** 条件とちょうど一致するとき、両者は同じ事象に賭けています。

例：2連複 1=2 が当たる ⇔ 2連単 1→2 か 2→1 のどちらか一方が当たる。

### 1.2 合成オッズ S

n 点に、**どれが当たっても払戻が同じになる** ように資金を配分します（ダッチング）。

```
S = 1 / (1/o₁ + 1/o₂ + … + 1/oₙ)
各点への配分 wₖ = W × S / oₖ   （W は総投資額）
払戻 = wₖ × oₖ = W × S          （どの点が当たっても同じ）
```

S は「n 点をまとめて 1 点として見たときのオッズ」です。`calc.js` の `syntheticOdds` は任意の点数に対応しています。

### 1.3 比率 R と判定

```
R = C / S
```

| R | 判定 |
|---|---|
| R > 1 | 賭式 T を 1 点で買うほうが得 |
| R < 1 | 組み合わせ n 点を合成して買うほうが得 |
| R ≈ 1 | 差なし（丸め誤差の範囲） |

- どちらも同じ事象に賭けているので、R は「同じ金額で当たったときの払戻の比」そのものです。
  的中確率の推定も不要です。
- 表示オッズには控除率が反映済みなので、控除率の補正はしません（ボートレースは全賭式 75%）。
- 強調表示のしきい値は初期値 R ≥ 1.10 / R ≤ 0.90 です（`DEFAULT_THRESHOLDS`）。

### 1.4 計算例（2連複 1=2）

a = 2連単 1→2 = 5.3、b = 2連単 2→1 = 12.0、C = 2連複 1=2 = 4.2 のとき

```
S = 1 / (1/5.3 + 1/12.0) = 3.676
R = 4.2 / 3.676 = 1.142   → 2連複が得（しきい値 1.10 超え）
```

1000 円を 2連単で合成する場合の配分は 1→2 に 694 円、2→1 に 306 円です。
どちらが当たっても払戻は約 3,676 円です。2連複 1=2 に 1000 円なら 4,200 円になります。

## 2. 賭式一覧

| 賭式 | 的中条件 | 組数 | 表示 | ページ |
|---|---|---|---|---|
| 単勝 | 1着を当てる | 6 | 単一値 | `oddstf` |
| 複勝 | 2着以内に入る 1 艇 | 6 | **範囲**（下限〜上限） | `oddstf` |
| 2連単 | 1着・2着を着順どおり | 30 | 単一値 | `odds2tf` |
| 2連複 | 1着・2着の 2 艇（順不同） | 15 | 単一値 | `odds2tf` |
| 拡連複 | 3着以内に入る 2 艇（順不同） | 15 | **範囲**（下限〜上限） | `oddsk` |
| 3連単 | 1〜3着を着順どおり | 120 | 単一値 | `odds3t` |
| 3連複 | 1〜3着の 3 艇（順不同） | 20 | 単一値 | `odds3f` |

ページの URL はいずれも `https://www.boatrace.jp/owpc/pc/race/<ページ>?rno=<R>&jcd=<場>&hd=<日付>` です。

複勝と拡連複は、1 レースに当たり組が複数あります（複勝 2 組、拡連複 3 組）。
払戻金は、一緒に当たる組がどれかによって変わります。そのため、オッズは範囲で表示されます（→ 4章）。

## 3. 等価な組み合わせ（包含関係）

左の 1 点と、右の n 点（互いに同時には当たらない）が同じ事象です。

| 1 点 | 等価な組み合わせ | 点数 |
|---|---|---|
| 2連複 i=j | 2連単 i→j, j→i | 2 |
| 3連複 i=j=k | 3連単 {i,j,k} の並べ方すべて | 6 |
| 2連単 i→j | 3連単 i→j→k（k は残り 4 艇） | 4 |
| 2連複 i=j | 3連単 i→j→k, j→i→k | 8 |
| 単勝 i | 2連単 i→x（x は残り 5 艇） | 5 |
| 単勝 i | 3連単 i→x→y | 20 |
| 複勝 i | 2連複 i=x（x は残り 5 艇） | 5 |
| 複勝 i | 2連単 i→x, x→i | 10 |
| 拡連複 i=j | 3連複 i=j=k（k は残り 4 艇） | 4 |
| 拡連複 i=j | 3連単 {i,j,k} の並べ方すべて（k は残り 4 艇） | 24 |

合成オッズは結合法則を満たします。たとえば「2連単 2点を合成したもの」をさらに 4 組合成すると、
「3連単 8点を直接合成したもの」と同じ値になります。つまり `1/S` を足し合わせるだけでよく、
途中の段階の合成オッズを再利用できます。

## 4. 賭式ごとの比較方法

### A. 2連複 i=j vs 2連単 2点 ― **実装済み**

| 項目 | 内容 |
|---|---|
| 対象 | 15 組 |
| 計算 | `S = 1/(1/a + 1/b)`（a = i→j, b = j→i）、`R = C/S` |
| ページ | `odds2tf` だけ（1 ページで完結） |
| 実装 | `compareRow` / `computeRows` / `classify`（`src/calc.js`） |

### B. 3連複 i=j=k vs 3連単 6点

| 項目 | 内容 |
|---|---|
| 対象 | 20 組 |
| 計算 | `S = 1/Σ(1/o)`（{i,j,k} の 6 通りの並び）、`R = C/S` |
| ページ | `odds3f` と `odds3t`（2 ページ） |

例：6 点のオッズが 18.5 / 32.1 / 25.4 / 60.2 / 41.0 / 88.3 なら S = 5.65 です。
3連複 C = 6.8 なら R = 1.20 で、3連複が得です。

### C. 2連単 i→j vs 3連単 4点

| 項目 | 内容 |
|---|---|
| 対象 | 30 組 |
| 計算 | `S = 1/Σ_k(1/o(i→j→k))`、`R = C/S` |
| ページ | `odds2tf` と `odds3t` |

3着を問わない買い方を 3連単で作れるかどうかを見る比較です。
同じデータから「2連複 i=j vs 3連単 8点」（15 組）も計算できます。

### D. 単勝 i vs 2連単 5点

| 項目 | 内容 |
|---|---|
| 対象 | 6 組 |
| 計算 | `S = 1/Σ_x(1/o(i→x))`、`R = C/S` |
| ページ | `oddstf` と `odds2tf` |

3連単 20 点で合成することもできます（`odds3t`）。

### E. 複勝 i vs 2連複 5点（範囲オッズ）

| 項目 | 内容 |
|---|---|
| 対象 | 6 組 |
| 計算 | `S = 1/Σ_x(1/o(i=x))`、`R_min = C_min/S`、`R_max = C_max/S` |
| ページ | `oddstf` と `odds2tf` |

### F. 拡連複 i=j vs 3連複 4点（範囲オッズ）

| 項目 | 内容 |
|---|---|
| 対象 | 15 組 |
| 計算 | `S = 1/Σ_k(1/o(i=j=k))`、`R_min = C_min/S`、`R_max = C_max/S` |
| ページ | `oddsk` と `odds3f` |

### 範囲オッズ（E・F）の判定

合成側の払戻は S で確定しています。いっぽう複勝・拡連複の払戻は、一緒に当たる組によって
下限〜上限のどこかに決まり、どこになるかはページからは分かりません。そこで両端で比べます。

| 条件 | 判定 |
|---|---|
| R_min > 1 | どの結果でも複勝／拡連複が得 |
| R_max < 1 | どの結果でも合成が得 |
| R_min ≤ 1 ≤ R_max | どちらとも言えない（結果しだい） |

しきい値も R_min（得側の判定）と R_max（損側の判定）に当てはめます。
例：3連複 4 点のオッズが 12.3 / 25.6 / 40.1 / 55.0 なら S = 6.12 です。
拡連複が 5.5〜7.5 なら R = 0.90〜1.23 で、「どちらとも言えない」になります。

## 5. 共通の注意点

- **丸め誤差**：オッズは 0.1 刻みなので、オッズ o には最大 ±0.05 の誤差があります（相対誤差 0.05/o）。
  低いオッズほど影響が大きく、C = 3.1 なら約 ±1.6% です。R が 0.95〜1.05 程度の差はノイズとして扱います。
  1000 倍以上は整数表示です（例「1244」）。
- **点数が多い合成**：3連単 20〜40 点の合成は、売れていない組を多く含みます。
  自分の購入でオッズが動きやすい（パリミュチュエル方式）ので、表示オッズどおりの払戻にならない可能性が高くなります。
- **100 円単位の購入**：配分 wₖ は 100 円単位に丸めることになるので、払戻は S どおりに均等にはなりません。
  点数が多く投資額が小さいほど、ずれが大きくなります。
- **欠場**：欠場艇を含む組は返還されるので、合成からは除外して問題ありません。等価性は残りの艇で成り立ちます。
  比べる側の 1 点（例：単勝 i）が欠場艇を含む場合は、その組自体を計算対象外にします。
- **発売票数 0（「0.0」表示）**：オッズが定まらないので、その組を含む比較は計算不可（「—」）にします（現行の挙動と同じ）。
- **ページ間の時間差**：B〜F は別ページのオッズを使います。それぞれの「オッズ更新時間」がずれていると、
  比較の前提が崩れます。保存時に更新時刻も持たせ、差が大きいときは警告を出すのが望ましいです。
  締切後は確定オッズに変わる点にも注意してください。
- **同着**：同着があると払戻の扱いが変わり、等価性が厳密には崩れます。まれなので考慮しません。

## 6. 実装する場合のデータ形式案

パーサーの出力は、既存の形式（`a: {"1-2": 5.3}`, `c: {"1=2": 3.1}`）にそろえます。

| 賭式 | キー例 | 値 |
|---|---|---|
| 単勝 | `"1"` | 数値 |
| 複勝 | `"1"` | `{ min, max }` |
| 2連単 | `"1-2"` | 数値 |
| 2連複 | `"1=2"` | 数値 |
| 拡連複 | `"1=2"` | `{ min, max }` |
| 3連単 | `"1-2-3"` | 数値 |
| 3連複 | `"1=2=3"` | 数値 |

別ページどうしの比較（B〜F）では、開いたページの解析結果を `chrome.storage.session` に
レース単位のキー（`race:<日付>_<場>_<R>:<賭式>`）で保存します。必要な賭式がそろったレースだけを突き合わせます。
ユーザーが開いたページだけを読み、別ページの fetch はしないという方針（README「守っていること」）は変えません。
