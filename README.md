# オッズ歪みチェッカー（自分用プロトタイプ）

開いているオッズページの表示内容を読み取り、**的中条件がまったく同じになる「1点買い」と「複数点買い」**の
合成オッズを比べて、どちらが得かをサイドパネルに表示する Chrome 拡張（Manifest V3）です。
スマホ（Android の Chrome）用にブックマークレット版もあります。

対象ページ：`https://www.boatrace.jp/owpc/pc/race/<種類>?rno=<R>&jcd=<場>&hd=<日付>`

| 種類 | ページ（「オッズ」のタブ） |
|---|---|
| `odds2tf` | 2連単・2連複 |
| `odds3t` | 3連単 |
| `odds3f` | 3連複 |
| `oddsk` | 拡連複 |

24場・全レース共通で動きます（場ごとの分岐はありません）。

## 比較の内容

合成オッズ **S = 1 / Σ(1/o)**（複数点の各点に 1/o の比率で配分したときの払戻倍率）と、
1点買いのオッズの比 **R = 1点買いのオッズ / S** を出します。

| 比較 | 1点買い | 複数点買い（同じ的中条件） | 必要なページ |
|---|---|---|---|
| 2連単2点 vs 2連複 | 2連複 i=j | 2連単 i→j, j→i（2点） | 2連単・2連複 |
| 3連単6点 vs 3連複 | 3連複 i=j=k | 3連単 i,j,k の並べ替え（6点） | 3連単 + 3連複 |
| 3連単4点 vs 2連単 | 2連単 i→j | 3連単 i→j→残りの艇（4点） | 2連単・2連複 + 3連単 |
| 3連複4点 vs 拡連複 | 拡連複 i=j | 3連複 i=j=残りの艇（4点） | 拡連複 + 3連複 |

- R > 1 → 1点買いのほうが得、R < 1 → 複数点買いのほうが得
- 全賭式の払戻率が同じ（75%）なので控除率の補正はしない
- オッズは 0.1 刻みで丸められているため、R が 0.95〜1.05 程度はノイズ扱い。
  強調表示のしきい値（初期値 R ≥ 1.10 / R ≤ 0.90）は「表示の設定」で変更できます。「しきい値を超えた組だけ表示」も選べます
- **拡連複**はオッズが「2.2-3.0」のような幅（実際の配当は3着の艇で決まる）なので、R も幅 [下限/S, 上限/S] で表示します。
  幅全体が上側しきい値以上なら拡連複、幅全体が下側しきい値以下なら3連複4点を強調し、幅が1をまたぐ組は「結果次第」と表示します
- **欠場**：欠場艇を含む組は対象外（「欠場」）。複数点のうち欠場艇を含む点は買えないので除いて合成します
  （例: 6号艇欠場なら 2連単 1→2 は 3連単 1→2→3/4/5 の3点と比較。点数が減った組は合成値の横に「（3点）」と表示）
- 発売票数0（「0.0」表示）などで1点でもオッズが欠ける組は計算できないので「—」で末尾に表示します
- 合成オッズは理想的に配分した場合の値です。100円単位で買うと配分を丸めるため、実際の払戻はこれより少し下がります

### 別ページどうしの比較について

3連単と3連複などは別ページなので、**ユーザーが同じレースの両方のページを開いたとき**に、それぞれの読み取り結果を
レースごとに保存して突き合わせます（別ページを自動で取得することはしません）。サイドパネル／結果ページには、
足りないページを開くボタン（「3連複を開く」など）が出ます。

別々のページのオッズは読み取った時刻が違います。比較ごとに各ページの「オッズ更新時間」を表示し、
発売中のページどうしで2分以上ずれているとき、または締切時オッズと発売中のオッズが混ざっているときは警告を出します。
締切後のページどうしなら、確定したオッズで比べられます。

## 導入手順（PC の Chrome：拡張機能）

1. GitHub のリポジトリページで **Code → Download ZIP** でダウンロードして、わかりやすい場所（例: `ドキュメント\odds-addon`）に展開する
   （git が使えるなら `git clone` でも可。更新は `git pull` で取り込めます）
2. Chrome で `chrome://extensions` を開く
3. 右上の **デベロッパーモード** をオン
4. **パッケージ化されていない拡張機能を読み込む** をクリックし、`manifest.json` があるフォルダを選ぶ
5. ツールバーの拡張機能アイコン（パズルのピース）から「オッズ歪みチェッカー」をピン留めしておくと便利
6. オッズページを開き、拡張機能のアイコンをクリックするとサイドパネルが開きます。
   同じレースの別のオッズページ（タブ切り替えやサイドパネルの「〇〇を開く」）を開くたびに、比較が増えていきます

※ 展開したフォルダを消したり移動したりすると拡張が読み込めなくなります。
コードを更新したら `chrome://extensions` で拡張機能の ⟳（再読み込み）を押し、オッズページもリロードしてください。
読み取った結果は `chrome.storage.session` に保存され、ブラウザを閉じると消えます（最大40レース分）。

## スマホ（Android の Chrome）で使う：ブックマークレット

Android の Chrome は拡張機能に対応していないため、同じ計算をする**ブックマークレット**を用意しています。
PC の Chrome で登録して、ブックマーク同期でスマホに送るのが一番簡単です。

1. ダウンロードしたフォルダの `dist/install.html` を PC の Chrome で開き、「オッズ比較」ボタンをブックマークバーへドラッグ
2. PC とスマホの Chrome で同じ Google アカウントにログインし、同期の「ブックマーク」をオン
3. スマホでオッズページを開き、**アドレスバーに「オッズ比較」と入力 → 候補の★ブックマークをタップ**
   （ブックマーク一覧からタップしても動きません。Android の Chrome の仕様です）
4. 結果ページが開きます。「3連複を開く」などのボタンで同じレースの別のオッズページへ移り、そこでもう一度実行すると、
   3連単×3連複などの比較も表示されます。「← オッズページに戻る」かブラウザの戻るで元のページへ
5. 最新のオッズで計算し直すときは、オッズページの「更新」を押してからもう一度実行

- 対象は PC 版のオッズページ（`/owpc/pc/race/…`）です。スマホから開いても PC 版がそのまま表示されます。
  スマホ版（`/owsp/sp/`）や単勝・出走表などのページで実行すると、同じレースの PC 版オッズページへ移動するか確認します
- 公式ページの DOM は書き換えず、結果は別ページ（Blob）に表示します。通信・外部送信はしません
- 読み取った結果と設定はその端末のブラウザ（boatrace.jp の localStorage）に保存されます（最大30レース分）
- 中身は拡張機能と同じ `src/parser.js` / `src/calc.js` / `src/view.js` です。ソースを変更したら
  `npm run build` で `dist/` を作り直してください（`npm test` が古い `dist/` を検出します）

## 守っていること

- 読むのは **ユーザーが開いているページの DOM だけ**。バックグラウンドでの定期取得や別ページへの fetch はしない
- 公式ページの DOM は書き換えない（表示はサイドパネル／別ページのみ）
- 外部へのデータ送信なし、外部ライブラリなし（素の JavaScript）
- コンテンツスクリプトはオッズページの URL パターンにだけ注入

## 構成

```
manifest.json
src/
  parser.js      Document → { type, meta, odds, absent }（純粋関数。ページの種類ごとにオッズを読む）
  calc.js        合成オッズ・比率・判定と4つの比較（純粋関数）
  view.js        比較の表と設定フォームの描画（サイドパネルとブックマークレットで共通）
  content.js     ページを解析して結果を送る／MutationObserver で再解析
  background.js  結果を chrome.storage.session に保存（tab:<id> とレースごとの race:<日付>_<場>_<R>）
sidepanel.html / sidepanel.css / sidepanel.js   サイドパネル
bookmarklet/     スマホ用ブックマークレットの本体（main.js）と結果ページ用スクリプト（result.js）
scripts/build-bookmarklet.js   dist/bookmarklet.txt と dist/install.html を生成
dist/            生成済みのブックマークレットと登録用ページ
fixtures/        オッズページの HTML（テスト用）
test/            node:test のユニットテスト（test/helpers/mini-dom.js はテスト専用の簡易 HTML パーサー）
```

データの流れ（拡張）：`content.js` →（`runtime.sendMessage`）→ `background.js` →（`storage.session`）→ `sidepanel.js`

`parser.js` の出力（`odds`）：

| type | odds |
|---|---|
| `2tf` | `{ a: {"1-2": 5.3, …}, c: {"1=2": 3.1, …} }` |
| `3t` | `{ t: {"1-2-3": 12.1, …} }` |
| `3f` | `{ f: {"1=2=3": 5.9, …} }`（艇番は昇順） |
| `k` | `{ k: {"1=2": [2.2, 3.0], …} }`（拡連複は [下限, 上限]） |

### ページ構造のメモ（パーサーが頼りにしているもの）

- ページの種類はオッズ種別タブの選択中の項目（`.tab4_tabs li.is-active`）、なければ URL のパス名で判定
- 見出し `.title7_mainLabel`（「2連単オッズ」「3連単オッズ」など）の直後の `.table1 table` を読む
- 列と1着艇（連複系は組の一方）の対応は `thead` の艇番 `th`（1〜6）から読む。オッズは `td.oddsPoint`
- 2艇の表（2連単・2連複・拡連複）：各行は「相手艇番 td + オッズ td」が列の数だけ並ぶ
- 3艇の表（3連単・3連複）：2着艇の td が `rowspan=4`。ブロック先頭行は列ごとに3セル（2着・3着・オッズ）、残りの行は2セル（3着・オッズ）
- 欠場は `td.oddsPoint.is-miss`（「欠場」）。その艇を含むセルがすべて欠場なら欠場艇とみなす。1000倍以上は「1244」のように小数点なし
- 場名は `.heading2_area img[alt]`（取れなければ jcd→場名の対応表）、レース番号などはオッズ種別タブのリンク
- 締切予定時刻は表示中レースの列から読む（`is-activeColor1` は「発売中のレース」の印なので使わない）

## fixtures

`<種類>_<日付>_<jcd>_<R>_<状態>.html`（状態: `live` 発売中 / `closed` 締切後 / `kekkajo` 欠場あり / `nodata` データなし）。
2連単・2連複は 2026-11-14 開催の14場分、3連単・3連複・拡連複は大村1R（締切後）・大村12R（発売中）・江戸川12R（6号艇欠場）と
翌日（データなし）を含みます。全 fixture に共通の性質（キー形式・組の数・メタ情報とファイル名の一致など）をテストしているので、
新しい場・状態のページを追加するとそのまま回帰テストになります。Chrome で保存する場合は「ウェブページ、完全」で保存し、
HTML ファイルだけを上の名前で置いてください（`*_files/` は `.gitignore` 済み）。
